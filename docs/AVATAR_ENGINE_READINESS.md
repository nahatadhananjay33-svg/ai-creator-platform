**Date:** 2026-07-05 · Verdict: **framework production-ready; model layer
gated on GPU hardware.** One real generation path exists today (SadTalker,
CPU, offline-batch only).

## Ready now

- **Operational avatar research platform**: installer (repo-clone +
  checkpoint prefetch, resumable, shared CLI with voice), compatibility
  detection, model validation battery, real-asset dataset (10 Kokoro-voiced
  scenario clips + 3 portraits), benchmark → evaluation → CSV/JSON/MD
  reporting — all exercised end-to-end with a real model this phase.
- **Two real adapters** (SadTalker, LivePortrait) behind the frozen
  `AvatarGenerator` interface; planned placeholders keep the other nine
  candidates enumerable and honestly SKIPPED.
- **Voice→Avatar integration proven**: benchmark lip-sync audio is
  generated by the production Voice Engine (Kokoro), closing the A1→A3 loop.
- 177 tests green; zero benchmark-only model code.

## Measured baseline (this host, CPU)

SadTalker: RTF 241–281 (mean ≈ 255), 256²@25fps, stable sharpness, motion
present, Hindi-driven generation works. LivePortrait: >60 min for ~5 s on
CPU (timeout) — not usable without GPU.

## Blockers for Phase A4 (Production Avatar Engine)

1. **GPU box or cloud GPU (the same P1 profile as voice A2)** — required
   for: LivePortrait/EchoMimic V3 evaluation, comparative quality rankings,
   identity + lip-sync metric backends, and any production rendering SLA.
   Without it the avatar engine remains a validated framework with one slow
   baseline model.
2. **WSL2** on the benchmark box — unlocks MuseTalk/LatentSync-class
   candidates (compiled-dep blockers verified on native Windows).
3. **Metric backends in model venvs** — install InsightFace (identity) and
   a SyncNet-class scorer (lip-sync) alongside the GPU pass so the
   evaluator's optional metrics activate; extend ResourceMonitor to sample
   child processes (subprocess adapters currently under-report memory).
4. **Consented human portraits** — benchmark currently uses SadTalker's
   example images; production/brand personas need licensed portraits
   (consent metadata flow mirrors voice profiles).

## Recommended A4 kickoff order

1. Stand up GPU/WSL2 (shared with voice A2 milestone 2 — one procurement).
2. Re-run this exact benchmark unscoped on GPU: all adapters × 10
   scenarios × identity/lip-sync metrics; merge with this CPU baseline.
3. Human eval round (blind sheets already implemented) → pick the
   production default and the cloud-tier model from *data*.
4. Only then build the production talking-avatar pipeline
   (avatar_engine/talking_avatar) around the winner, consuming
   `voice_engine.SynthesisResult` timestamps for lip-sync.

## Interim capability statement

Until A4 hardware lands, the platform can honestly offer: **offline avatar
clips (SadTalker 256², minutes-per-second)** voiced by the real-time voice
engine — suitable for internal demos and content experiments, not for
customer-facing rendering SLAs.
